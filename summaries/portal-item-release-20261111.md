# Portal item release

Source: `a66c9209d`. Shared-load follow-up: `03a9efeaf`. Combined schema:
`dbc086852`, version 458. Presentation merge: `df6e93285`.

An item in custody keeps its last independent body material and records the
holder material at pickup. Release applies the later holder transform to the
item's retained material. It keeps the item's canonical dimensions and
identity. The root chart comes from the native material partition, so a hand
can release an item through an aperture before the holder's centre crosses.
The instance uses its own piece budget. A new quantity uses the room budget
and holder material. Portal surface motion enters the velocity conversion.

Release is prepared before hand, custody, stock or identity-counter changes.
A failed real-object release cannot enter the quantity mint path. Menu hand
changes prepare all affected items before they commit. Participant leave
prepares its releases before it changes membership or retires bodies. NPC
carry decisions retain custody on refusal. A shared load uses its existing
sling anchor when its supporter is in the same room. Reconstruction binds the
material basis to the restored holder; this is not a durable pose archive.
The basis is canonical rollback state and returns to identity in the world.

## Behavioral evidence

The owner checks retain an item's own material while the holder changes
scale and reflection, release in the far chart before the holder crosses,
refuse without losing the object or minting a replacement, and keep a hand
on a refused stow. The mint check refuses first, then confirms that the
accepted mint still gets sequence zero. The shared-load case checks the
sling anchor after an admitted stow.

The app case uses station H's authored javelin, by its stable identity. Its
holder starts at scale 0.75; the javelin starts at scale 1.25 with a turn.
After the holder crosses the 80/40 pair, it drops the same javelin at scale
0.625 with reflection. The javelin keeps its canonical dimensions and remains
in the world. Real GGRS loads run, and a second complete run gives the same
body bytes. The fixture uses the existing authored item; it does not add a
second copy beside it. No map or art changed.
